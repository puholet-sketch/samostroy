# Решения спринта (контроль / площадь / акты / KPI)

Дата фиксации: 2026-10-29.

## Locked

1. Площадь на объекте → автозаполнение **дизайн + ремонт + смета**.
2. Несколько версий расчёта на объект; одна становится **согласованной** после подтверждения клиента.
3. Из согласованной версии по умолчанию: **договор + смета** (не акт).
4. Еженедельный отчёт клиенту = сборка из дневных отчётов прораба; день отчёта **пятница**; неделя **сб→пт**.
5. Уведомления **email + Telegram** → пользователь **+79773639300**, прораб, Даниил (владелец). В ролях Security нужны поля **телефона**; отправка через Termux/phone-bot где возможно.
6. **Дата начала работ** хранится на карточке объекта.
7. Баг контроля: сохранённый отчёт не виден при повторном открытии карточки (reload / token / merge API) — не только cross-device.
8. **Синхронизация фото** между устройствами (MVP: upload media blobs на API вместе с отчётом).
9. Статус **«в работе»** на объекте; клиент наследует/фильтруется, если ≥1 объект в работе.
10. Этапы = **этапы договора** (не путать с нумерацией актов).
11. KPI-неделя = **сб–пт**.
12. Порядок спринта: **bugs → area → acts from calculator → week KPI**, далее versions / filters / weekly pack / notifications по ёмкости.

## Сделано в релизе 2026-10-29-a

- P0: таймаут API, локальное сохранение всегда, refresh календаря, media upload API.
- P1: `areaM2` / `startDate` / `inWork` на объекте + autofill документов.
- P2: акт из калькулятора (чекбоксы + этапы по разделам).
- P3: KPI недели сб–пт в шапке контроля (все объекты).
- Фильтры сводного отчёта + каркас версий расчёта.

## Сделано в релизе 2026-10-29-b

- Полный UI версий расчёта: статусы «расчёт» / «согласованный», сохранить / загрузить / согласовать / снять / переименовать / удалить; из согласованной — договор + смета.
- Еженедельный пакет клиенту: `/control/weekly-pack`, неделя сб→пт, день за днём, навигация по фото стрелками, печать/PDF.
- Дедлайны этапов от `startDate` → email (Web3Forms) + Telegram (`POST /api/notify`); получатели: **+79773639300** + телефоны owner/foreman из Security.
- Поле **телефона** на учётке в Настройках.
- Реестр клиентов: фильтр и KPI «в работе» (≥1 объект `inWork`).

## Инфра (честно)

- **Telegram-доставка** требует: Docker API (`bots/feedback-bot`) + `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` + публичный туннель (ngrok), иначе канал skipped / только email.
- **Фото в weekly pack** на другом устройстве — только если media залиты на API; иначе IndexedDB того же браузера.
- Phone-bot / Termux SMS — опционально поверх телефонов в Security; в MVP маршрутизация идёт в TG chat бота + email.
