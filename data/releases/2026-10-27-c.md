# Pro: Pages на стабильном ngrok к локальному API

Публичный HTTPS для замечаний и отчётов переведён с временного cloudflared на **ngrok** (free hostname). Пока ПК включён, Docker и `ngrok http 8787` работают — CRM на GitHub Pages ходит в ту же Postgres.

## Зачем бизнесу

- Один общий API для заказчика и менеджера с публичного сайта.
- Hostname ngrok предсказуемее в рамках сессии; после рестарта туннеля URL нужно обновить и пересобрать Pages (или поправить в «Безопасность»).

## Как устроено

1. `docker compose up -d` — API `:8787`.
2. `ngrok http 8787` — публичный `*.ngrok-free.dev`.
3. Сборка Pages печёт `VITE_FEEDBACK_API_URL`; CRM шлёт `X-Feedback-Token` и `ngrok-skip-browser-warning`.

## Ежедневно

ПК не засыпает. После перезагрузки: Docker + ngrok. Новый hostname → обновить URL и деплой. Инструкция: `docs/modules/pro-local-ngrok.md`.

## Как проверить

1. Маркер сборки: `2026-10-27 · pro ngrok c`.
2. С другого устройства: замечание / дневной отчёт → запись в API на этом ПК.
3. `…/health` и `GET /api/feedback` с токеном через публичный URL.
