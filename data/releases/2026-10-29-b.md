# Версии расчёта, пакет клиенту, уведомления и фильтр «в работе»

Закрываем всё, что в решениях спринта 29.10 было в блоке «отложено»: полный контур версий, еженедельный пакет, дедлайны этапов, телефоны в Security и фильтр клиентов.

## Зачем бизнесу

- Можно хранить несколько вариантов сметы на объект, согласовать один — и сразу собрать **договор + смету** (не акт).
- По пятницам клиенту уходит понятный пакет за неделю **суббота→пятница**: день за днём, коротко что сделано, фото со стрелками.
- Дедлайны этапов договора считаются от **даты старта** объекта; команда получает письмо и (при живом API) Telegram. В списке всегда **+79773639300**, плюс телефоны прораба и Даниила из учёток.
- В реестре клиентов видно, у кого объекты **в работе**, и можно отфильтровать только их.

## Как проверить

### Версии расчёта

1. Калькулятор → заполнить → Договоры → выбрать клиента и объект.
2. «Сохранить снимок» → статус **расчёт**.
3. «Согласовать» → статус **согласованный** (остальные снова расчёт).
4. «Договор + смета из согласованной» → вкладки ремонта и сметы заполнены → сгенерировать оба DOCX.

### Еженедельный пакет

1. `/control` → клиент + объект → **Пакет клиенту (сб→пт)**.
2. Стрелки недель, день за днём; если есть фото — стрелки влево/вправо.
3. Печать / PDF в браузере.

### Уведомления и телефоны

1. Настройки → учётки: указать телефоны Даниила (owner) и прораба.
2. Настройки → Замечания / API → блок «Дедлайны этапов» → **Проверить и отправить**.
3. Email уходит через Web3Forms при настроенном ключе.
4. Telegram — только если Docker API + `TELEGRAM_*` + ngrok живы; иначе в логе «пропуск».

### Клиенты «в работе»

1. `/clients` → KPI «В работе» и чекбокс **Объект в работе**.
2. В таблице колонка с числом объектов inWork.

Маркер сборки: `2026-10-29 · versions weekly notify b`.

## Честно про инфру

Без **Docker + feedback-bot + TELEGRAM_BOT_TOKEN/CHAT_ID + ngrok** Telegram-канал не доставит сообщение (email всё равно может). Фото в пакете на другом телефоне — только после upload media на API.
